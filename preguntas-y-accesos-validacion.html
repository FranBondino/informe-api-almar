📋 Guía Completa de Requerimientos, Accesos y Validación

Lista estructurada de preguntas con su fundamentación técnica y los accesos concretos necesarios para comenzar el desarrollo inmediatamente sin bloqueos.

🔑 1. Accesos y Entregables Técnicos Requeridos para Iniciar

1.1 API Token de Producción / Staging de Kipintoch ✅ YA DISPONIBLE

Token de autenticación HTTP Header token: <API_TOKEN> para interactuar con los endpoints de carpetas, empresas, gastos y rentabilidad.

¿Qué destraba? Permite la conexión directa del backend con la base de datos de Kipintoch para consultar y registrar costos.
Estado Actual Validado y mapeado correctamente en la documentación oficial.
1.2 Conector de Email corporativo (Microsoft 365 / Gmail / IMAP) 🔴 BLOQUEANTE

Permisos de lectura en el servidor de correo para la captura automática de comprobantes entrantes.

¿Por qué lo pedimos? Para programar la ingesta automática de adjuntos PDF sin requerir que los empleados reenvíen manualmente los correos.
Cómo pedirlo en la reunión "¿Nos autorizan la app en Microsoft 365 con permiso Mail.Read o nos configuran una casilla de ingesta facturas@almarrosario.com?"
1.3 Dataset de Prueba (10 a 20 Facturas Reales en PDF) 🔴 BLOQUEANTE

Mapeo de comprobantes heterogéneos recibidos recientemente (Maersk, MSC, despachantes, fletes locales e Invoices en USD).

¿Por qué lo pedimos? Para calibrar los prompts del modelo de Inteligencia Artificial / OCR y garantizar una tasa de extracción de datos >95%.
Cómo pedirlo en la reunión "¿Nos pueden enviar un paquete comprimido con 15 facturas reales variadas que hayan recibido este mes para entrenar el bot?"

🔴 2. Preguntas de Prioridad Máxima Definición de Arquitectura

2.1 Sistema de Email Corporativo en Uso Prioridad 1
Fundamentación Técnica Determina qué SDK o protocolo de integración utilizamos en el Módulo 1 (Microsoft Graph API, Google Cloud Pub/Sub o IMAP IDLE universal).
Pregunta Formulada "¿Su correo corporativo corre bajo Microsoft 365, Google Workspace o tienen servidor propio con webmail?"
2.2 Mapeo de Casillas de Entrada Operativas Prioridad 2
Fundamentación Técnica Permite configurar los listeners multicasilla si las facturas ingresan a cuentas individuales (`operador1@almar.com`, `operador2@almar.com`).
Pregunta Formulada "¿A cuántas casillas diferentes llegan facturas hoy y cómo se distribuyen entre los empleados?"
2.3 Clave Primaria de Matcheo con Carpeta Prioridad 3
Fundamentación Técnica Establece el algoritmo de búsqueda de coincidencia exacta en Kipintoch (`numeroGuia`, `numeroBooking`, o `referenciaExterna`).
Pregunta Formulada "¿Cuál es el dato clave que usan hoy de memoria para encontrar la carpeta asociada a una factura recibida?"

🟡 3. Preguntas de Lógica de Negocio y Edge Cases Reglas del Bot

3.1 Rol y Responsabilidad del Aprobador en Dashboard Prioridad Alta
Fundamentación Técnica Define los roles, permisos y flujo de trabajo en la interfaz (Operadores de Carpeta vs Administración/Finanzas).
Pregunta Formulada "En la pantalla de 1-Clic, ¿quién debe revisar y dar la aprobación final: el operador asignado o el área de Administración?"
3.2 Umbral de Tolerancia para Alertas de Desvío de Costo Prioridad Alta
Fundamentación Técnica Permite parametrizar la consulta a `GET /rentabilidad` para activar banderas amarillas o rojas si el costo supera el valor estimado.
Pregunta Formulada "¿Con qué porcentaje de diferencia entre el costo facturado y el costo estimado cotizado deben encenderse las alertas de margen?"
3.3 Gestión de Comprobantes Multi-Ítem (Split de Gastos) Prioridad Alta
Fundamentación Técnica Define si el bot debe realizar el split automático de ítems (ej: separar Flete `FMA` de gastos locales `THC` y `DOC`).
Pregunta Formulada "¿Un mismo comprobante de Maersk o MSC suele contener varios conceptos de gastos que deban imputarse por separado?"
